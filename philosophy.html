Computing Philosophy

I value simplicity, transparency, and control over my tools. I prefer systems that expose their internals rather than hide them. Abstractions are useful — until they aren't. When they get in the way, I’d rather remove them than fight them.

My goal isn’t to reinvent the wheel, just to understand how it works and more importantly: why it was made the way it is.

To further this point, below is my personal computing experience.

Everyone asks Well, what is your favourite? To be honest, I really don't know. To be frank, it's easier to point out which one I dislike the most.

Unsurprisingly, it's Windows. But it's not for the stupid reasons that most people online spout. It's very simply that I want my machine to do what I want it to do. I want this program gone? It should be gone immediately. I want a certain GUI element to look different? It should be that way quickly. This is why the non-proprietary UNIX-like OSes like BSD and Linux are great. They aren't perfect by any means, but they are the best at my disposal.

As for my favourite OS, it probably has to be Debian. I know, it's a little cliche, but man it does the trick. When I install Debian, I know exactly what I'm getting. No extranous packages like Mint or Ubuntu, but no crazy problems like Arch or BSD. Just a simple computing environment to get work done.

However, I've seen the problems with systemd. It's useful for sure, but a lot of bloat. So I've fiddled in the past with Void Linux. It uses runit as it's init system, and to set a systemd-like service, its a simple as

  1. Set up a directory with run script in /etc/sv
  2. Simply do ln -s /etc/sv/"service name" /var/service
  3. Done
You want to remove a service? Simply rm -rf /var/service/"service name". Done.

In addition, you have the rv program that allows you to check status of of services, stop and restart them, etc. Really exceptional design, super easy to use. Is it easier than systemd? I won't say.

For more information on my use of void, please go to the "Projects" section of this page.
